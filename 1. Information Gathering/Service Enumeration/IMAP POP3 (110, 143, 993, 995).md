# IMAP / POP3 (110, 143, 993, 995)

---

## Overview

Both protocols retrieve email from a mail server; **SMTP sends** it. They differ in what they can do with mailboxes:

| |**IMAP**|**POP3**|
|---|---|---|
|**Default port**|`143` (clear-text / STARTTLS), `993` (implicit TLS/SSL)|`110` (clear-text / STLS), `995` (implicit TLS/SSL)|
|**Mail management**|Online management directly on the server: folder structures, hierarchical mailboxes, multiple mailboxes per session, preselection of emails|Only listing, retrieving, and deleting|
|**Synchronization**|"Network file system" for emails — uniform state across several independent clients; emails stay on server until deleted|Downloads to client; no real sync concept|

#### IMAP Key Facts

- Client-server protocol, text-based ASCII commands on port `143`.
- Commands can be sent in succession without waiting for confirmation — each carries an identifier/tag so responses can be matched later.
- Authentication (username + password) happens immediately after connect; mailbox access only after successful auth.
- Multiple users can access the server simultaneously.
- Without an active connection, managing emails is impossible (some clients offer offline mode with local copy + re-sync on reconnect).
- Copying sent mail into an IMAP folder makes it visible to all clients; personal folder structures improve organization but increase server storage needs.

> [!warning] Clear-text by default
> Without further measures IMAP transmits commands, emails, usernames, and passwords in plain text. Servers should enforce encrypted sessions via SSL/TLS (port `143` w/ STARTTLS or alternative port `993`).

```

```

## IMAP Commands

|**Command**|**Description**|
|---|---|
|`1 LOGIN username password`|User's login.|
|`1 LIST "" *`|Lists all directories.|
|`1 CREATE "INBOX"`|Creates a mailbox with a specified name.|
|`1 DELETE "INBOX"`|Deletes a mailbox.|
|`1 RENAME "ToRead" "Important"`|Renames a mailbox.|
|`1 LSUB "" *`|Returns a subset of names that the user has declared as active/subscribed.|
|`1 SELECT INBOX`|Selects a mailbox so its messages can be accessed.|
|`1 UNSELECT INBOX`|Exits the selected mailbox.|
|`1 FETCH <ID> all`|Retrieves data associated with a message in the mailbox.|
|`1 CLOSE`|Removes all messages with the Deleted flag set.|
|`1 LOGOUT`|Closes the connection with the IMAP server.|

*(The leading `1` is the command tag used to match server confirmations.)*

## POP3 Commands

|**Command**|**Description**|
|---|---|
|`USER username`|Identifies the user.|
|`PASS password`|Authenticates the user using its password.|
|`STAT`|Requests the number of saved emails from the server.|
|`LIST`|Requests the number and size of all emails.|
|`RETR id`|Requests delivery of the requested email by ID.|
|`DELE id`|Requests deletion of the requested email by ID.|
|`CAPA`|Requests the server to display its capabilities.|
|`RSET`|Requests the server to reset the transmitted information.|
|`QUIT`|Closes the connection with the POP3 server.|

## Dangerous Settings

Improper configuration can leak debug info or allow anonymous login (similar to FTP). Worst case: reading all sent/received email, which may hold confidential/sensitive data.

|**Setting**|**Description**|
|---|---|
|`auth_debug`|Enables all authentication debug logging.|
|`auth_debug_passwords`|Adjusts log verbosity; submitted passwords and their scheme get logged.|
|`auth_verbose`|Logs unsuccessful authentication attempts and their reasons.|
|`auth_verbose_passwords`|Passwords used for authentication are logged (can be truncated).|
|`auth_anonymous_username`|Username to use when logging in with the ANONYMOUS SASL mechanism.|

Many companies use third-party providers (Google, Microsoft), but self-hosted mail servers exist for privacy reasons — these are where misconfigurations are most likely.

## Footprinting the Service

Ports: `110`/`995` = POP3, `143`/`993` = IMAP (higher ports = TLS/SSL).

#### Nmap

```
tylapcheong@htb[/htb]$ sudo nmap 10.129.14.128 -sV -p110,143,993,995 -sC
```

What the output reveals:
- **Service + version** per port (e.g. `Dovecot pop3d`, `Dovecot imapd`)
- **Capabilities** = commands/features available on each port (e.g. `pop3-capabilities: AUTH-RESP-CODE SASL STLS TOP UIDL ...`, `imap-capabilities: ... STARTTLS ...`)
	- Port `143` showed `LOGINDISABLED` → plain LOGIN not allowed until STARTTLS; port `993` showed `AUTH=PLAIN` → login allowed over TLS
- **Embedded SSL certificate**: `CN=mail1.inlanefreight.htb`, org `Inlanefreight`, California → hostname, company, and location intel for free

If credentials for any employee are found, we can log in and read (or send) messages.

#### cURL — List Mailboxes

```
tylapcheong@htb[/htb]$ curl -k 'imaps://10.129.14.128' --user user:p4ssw0rd

* LIST (\HasNoChildren) "." Important
* LIST (\HasNoChildren) "." INBOX
```

#### cURL Verbose (-v)

With `-v` we see the full handshake: TLS version (`TLSv1.3` / cipher suite), SSL certificate details (**including an email address**, e.g. `emailAddress=cry0l1t3@inlanefreight.htb`), whether it's self-signed, and the **banner with the server software version** (`* OK [CAPABILITY ...] HTB-Academy IMAP4 v.0.21.4`) plus post-login capabilities after AUTHENTICATE.

```
tylapcheong@htb[/htb]$ curl -k 'imaps://10.129.14.128' --user cry0l1t3:1234 -v
```

#### OpenSSL — TLS Encrypted Interaction

Interactive session over POP3S/IMAPS; certificate chain shown first, then the server banner appears at the end (`+OK HTB-Academy POP3 Server` / `* OK [CAPABILITY IMAP4rev1 ... AUTH=PLAIN] HTB-Academy IMAP4 v.0.21.4`). From here, issue the IMAP/POP3 commands above directly.

```
tylapcheong@htb[/htb]$ openssl s_client -connect 10.129.14.128:pop3s
tylapcheong@htb[/htb]$ openssl s_client -connect 10.129.14.128:imaps
```

(`ncat --ssl` works as well.)

## Workflow Cheat Sheet

1. Nmap scan `-p110,143,993,995 -sC` → versions, capabilities, certificate info
2. Note `LOGINDISABLED` vs `AUTH=PLAIN` to know if clear-text login is possible per port
3. Grab banner/cert details (hostname, org, email addresses, server version)
4. Test found credentials (e.g. from SMTP enumeration — `robin:robin`) against IMAP/POP3
5. Once logged in: `LIST "" *` → `SELECT INBOX` → `FETCH <ID> all` (IMAP), or `STAT`/`LIST` → `RETR <id>` (POP3)
