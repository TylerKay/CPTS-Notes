# R-Services (512, 513, 514)

---

## Overview

`R-Services` are a suite of services enabling **remote access / issuing commands between Unix hosts** over TCP/IP. Developed by the Computer Systems Research Group (CSRG, UC Berkeley); the de facto standard for remote Unix access **until SSH replaced them** due to inherent security flaws.

- Like telnet: all client↔server traffic is **unencrypted** → MITM interception of passwords/login info.
- Span ports **512, 513, 514**; only accessible through the **r-commands** suite.
- Most common on commercial Unix: Solaris, HP-UX, AIX. Rare nowadays but still encountered in internal pentests.

Full r-commands suite: `rcp`, `rexec`, `rlogin`, `rsh`, `rstat`, `ruptime`, `rwho`.

## Frequently Abused R-Commands

|**Command**|**Service Daemon**|**Port**|**Transport**|**Description**|
|---|---|---|---|---|
|`rcp`|rshd|514|TCP|Copy a file/directory bidirectionally local→remote or remote→remote. Works like `cp` but gives **no warning when overwriting existing files**.|
|`rsh`|rshd|514|TCP|Opens a shell on a remote machine **without a login procedure**. Relies on trusted entries in `/etc/hosts.equiv` and `.rhosts`.|
|`rexec`|rexecd|512|TCP|Run shell commands remotely. Requires username/password over an **unencrypted** socket — overridden by trusted entries in `hosts.equiv`/`.rhosts`.|
|`rlogin`|rlogind|513|TCP|Log in to a remote host (like telnet, Unix-like hosts only). Authentication overridden by trusted entries in `hosts.equiv`/`.rhosts`.|

## Access Control & Trusted Relationships

The core weakness that motivated SSH's replacement of r-services:

- Default auth uses **PAM**, but it is **bypassed** by trusted-host files:
	- `/etc/hosts.equiv` → **global**: applies to all users on a system
	- `~/.rhosts` → **per-user** configuration
- Both files list `<username> <ip address>` or `<username> <hostname>` pairs of hosts/users trusted by the local host.
- The **`+` modifier is a wildcard meaning "anything"** — e.g. `+ 10.0.17.10` lets *any* external user access r-commands as the listed account.

```
tylapcheong@htb[/htb]$ cat /etc/hosts.equiv

# <hostname> <local username>
pwnbox cry0l1t3
```

```
tylapcheong@htb[/htb]$ cat .rhosts

htb-student     10.0.17.5
+               10.0.17.10
+               +
```

Misconfigurations here allow authenticating as another user **without any credentials** — potentially code execution.

## Footprinting

#### Nmap Scan

```
tylapcheong@htb[/htb]$ sudo nmap -sV -p 512,513,514 10.0.17.2

PORT    STATE SERVICE    VERSION
512/tcp open  exec?
513/tcp open  login?
514/tcp open  tcpwrapped
```

#### Log In via Trusted Relationship

```
tylapcheong@htb[/htb]$ rlogin 10.0.17.2 -l htb-student

Last login: Fri Dec  2 16:11:21 from localhost
[htb-student@localhost ~]$
```

No credentials needed — the misconfigured `.rhosts` file did the authentication.

#### Enumerate Logged-In Users Network-Wide

```
tylapcheong@htb[/htb]$ rwho

root     web01:pts/0 Dec  2 21:34
htb-student     workstn01:tty1  Dec  2 19:57  2:25
```

Maps usernames → hosts across the network (great for building target username lists). The `rwho` daemon periodically broadcasts this info → worth watching network traffic.

More detail with `rusers` (username, host, TTY, login date/time, idle time since last keystroke, source host):

```
tylapcheong@htb[/htb]$ rusers -al 10.0.17.5

htb-student     10.0.17.5:console          Dec 2 19:57     2:25
```

## Workflow Cheat Sheet

1. Nmap `-p 512,513,514 -sV` → detect exec/login/tcpwrapped (signs of r-services)
2. Look for `/etc/hosts.equiv` and `.rhosts` if we have any file read — hunt for `+` wildcards
3. `rlogin <IP> -l <user>` → attempt passwordless login via trust relationships
4. `rwho` / `rusers -al` → enumerate active users across the network for further attacks
5. Remember traffic is unencrypted — sniffing these services yields credentials directly
