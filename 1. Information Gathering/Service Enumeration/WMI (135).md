# WMI (135)

---

## Overview

`Windows Management Instrumentation` (`WMI`) is Microsoft's implementation **and extension** of the **Common Information Model (`CIM`)** — core functionality of the standardized **Web-Based Enterprise Management (`WBEM`)** for the Windows platform.

- Allows **read AND write access to almost all settings** on Windows systems.
- → The most critical interface in the Windows environment for administration and remote maintenance of PCs and servers alike.
- Not a single program: consists of several programs plus various databases (**repositories**).
- Typically accessed via: **PowerShell**, **VBScript**, or the **Windows Management Instrumentation Console (`WMIC`)**.

## Footprinting the Service

#### Port Behavior

WMI communication initialization **always takes place on TCP port 135**. After the connection is successfully established, communication moves to a **random port** — keep this in mind for firewall/scan considerations.

#### wmiexec.py (Impacket)

Executes commands through WMI given valid credentials:

```
tylapcheong@htb[/htb]$ /usr/share/doc/python3-impacket/examples/wmiexec.py Cry0l1t3:"P455w0rD!"@10.129.201.248 "hostname"

[*] SMBv3.0 dialect used
ILF-SQL-01
```

Note it negotiates over SMB (v3.0) as transport after the initial WMI interaction.

## Workflow Cheat Sheet

1. Confirm TCP 135 open → WMI entry point present
2. With credentials, run commands remotely: `wmiexec.py '<user>:"<pass>"@<IP>' "<command>"` (no shell — one command per execution)
3. Remember post-init traffic hops to random ports — don't rely on 135 alone for detection/firewall rules
4. WMI = read *and* write access to nearly all system settings → powerful once any creds are obtained; pairs well with PowerShell/WMIC for enumeration on-box
