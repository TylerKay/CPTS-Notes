Deeper dive into system internals — interfaces, users, processes, packages, and configs — to build a full picture of the target before moving to permissions enumeration.

## Network Interfaces
```bash
ip a
# alt: ifconfig (needs net-tools package, may not be present)
```
- Reveals interface names, IPs, and whether the host bridges into other subnets previously unreachable from the attack host.

## Hosts File
```bash
cat /etc/hosts
```
- Check for interesting static hostname/IP mappings.

## User Activity

**Last login times per user** — gauges how actively the system/users are used (more activity = more potential misconfigs/messy histories):
```bash
lastlog
```

**Currently logged-in users:**
```bash
w
# alt: who, finger
```

**Command history** — look for passwords in CLI args, git usage, cron setup:
```bash
history
```

**Special/hidden history files** (e.g. created by monitoring scripts):
```bash
find / -type f \( -name *_hist -o -name *_history \) -exec ls -l {} \; 2>/dev/null
```

---

## Cron Jobs
```bash
ls -la /etc/cron.daily/
```
- Combined with relative paths or weak permissions, cron jobs are a common privesc vector.

## /proc Filesystem
- Virtual filesystem, dynamically generated by the kernel — exposes process state, kernel params, memory, devices.
```bash
find /proc -name cmdline -exec cat {} \; 2>/dev/null | tr " " "\n"
```
- Can reveal command-line arguments of running processes (sometimes including credentials).

## Installed Packages & Binaries

**List installed packages** (older/outdated packages = higher vuln likelihood, even on newer distros):
```bash
apt list --installed | tr "/" " " | cut -d" " -f1,3 | sed 's/[0-9]://g' | tee -a installed_pkgs.list
```

**Check sudo version** for known exploits:
```bash
sudo -V
```

**List standalone binaries** (not all software is a "package" — some are just compiled binaries):
```bash
ls -l /bin /usr/bin/ /usr/sbin/
```

**Cross-reference installed binaries against GTFOBins** to flag exploitable ones:
```bash
for i in $(curl -s https://gtfobins.org/api.json | jq -r '.executables | keys[]'); do 
  if grep -q "$i" installed_pkgs.list; then echo "Check for GTFO: $i"; fi
done
```

## Tracing & Behavior Analysis

**strace** — trace system calls & signals to understand how a program accesses resources, processes signals, and sends/receives data. Useful for spotting credential/token leaks in requests to remote hosts.
```bash
strace ping -c1 <target_ip>
```
- Output can be redirected to a file for later analysis.

---

## Config Files & Scripts

**Config files** — readable if permissions allow (even without folder read access if file itself is world-readable). Often reveal service setup details and sensitive paths/keys:
```bash
find / -type f \( -name *.conf -o -name *.config \) -exec ls -l {} \; 2>/dev/null
```

**Shell scripts** — admin-created scripts often reveal internal processes, and sometimes carry weak permissions:
```bash
find / -type f -name "*.sh" 2>/dev/null | grep -v "src\|snap\|share"
```

**Running processes by user** — shows what's actively executing as root; scripts/binaries in an admin's PATH with loose permissions could be run without needing root access directly:
```bash
ps aux | grep root
```
